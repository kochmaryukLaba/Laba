# Прогресс

ЛР1 — старт проекта
- Создан проект React + TypeScript + Vite
- Заменён стартовый экран на Task Tracker (заголовок, описание, заглушка списка)
- Проверена сборка: `npm run build` проходит без ошибок

ЛР2 — страницы и навигация
- Добавлен React Router (`react-router`), подключён `BrowserRouter` в `main.tsx`
- Описан тип `Task` и создан массив из пяти демонстрационных записей (`types/task.ts`, `data/tasks.ts`)
- Создан переиспользуемый компонент `TaskCard` с типизированными props
- Собраны страницы: список задач (`TasksPage`), подробности по `:id` (`TaskDetailsPage`), заглушка создания (`NewTaskPage`), неизвестный адрес (`NotFoundPage`)
- Создан общий `AppLayout` с навигацией (`NavLink`) и `Outlet`
- Настроены маршруты в `App.tsx`: `/`, `/tasks`, `/tasks/:id`, `/tasks/new`, `*`
- Проверены сценарии: прямое открытие карточки, пустой список, переходы по `Tab`, отсутствие полной перезагрузки страницы при навигации
- Проверена сборка: `npm run build` и `npm run preview` проходят без ошибок

ЛР4 — загрузка справочника по HTTP
- Справочник тегов: `frontend/public/demo/tags.json` (id: study, work, home, health, personal), в браузере доступен по адресу `/demo/tags.json`
- Тип варианта: `frontend/src/types/tag.ts`; в `Task.tag` теперь хранится id тега, а не отображаемое имя
- Демонстрационные задачи (`frontend/src/data/tasks.ts`) переведены на id: «Учёба» → `study`, «Жизнь» → `personal`
- HTTP-сервис `frontend/src/services/tags.ts`: `fetch` с `cache: 'no-store'`, проверка `response.ok`, разбор ответа как `unknown`, проверка структуры (`isTag`, `parseTags`) и уникальности id
- Хук `frontend/src/hooks/useTags.ts`: состояния loading / error / success, `AbortController` и флаг `active` в очистке эффекта, `retry` через счётчик `attempt`
- `TaskForm`: текстовое поле тега заменено на `select` с вариантами из справочника; сообщения о загрузке, ошибке, пустом справочнике и неизвестном теге; кнопка «Повторить»; сохранение блокируется `canSave` и в `handleSubmit`, и через `disabled`
- Основные задачи по-прежнему живут в состоянии `App` и после перезагрузки страницы возвращаются к демонстрационному набору

Проверки ЛР4 (DevTools → Network, фильтр `tags.json`, Disable cache):

9. Исходный JSON и обычная сеть: CRUD, отмена, фильтр по статусу работают; смена тега с последующей отменой не меняет запись.
10. `npm run build` и `npm run preview`: файл `dist/demo/tags.json` есть в сборке, форма загружает справочник.

ЛР5 — схема данных и справочник в Supabase

Схема (миграция `supabase/migrations/202611081815_initial_schema.sql`):

| Таблица | Назначение | Ключ | Связь | Доступ |
|---|---|---|---|---|
| `public.tags` | справочник тегов задач | PK `id text` (study, work, home, health, personal), `name` unique | — | публичный: `anon` и `authenticated` только SELECT |
| `public.tasks` | личные задачи пользователя | PK `id uuid` | FK `owner_id` → `auth.users(id)`, FK `tag_id` → `tags(id)` | личная: RLS включён, прав и политик нет до ЛР 6 |

Ограничения: `NOT NULL` на обязательных полях; `CHECK` — непустые `id`/`name` без пробелов по краям, длина `title` 3–100, `status` ∈ {В планах, В процессе, Завершено}, `priority` ∈ {не горит, средний, горит}. Поле `tag` во frontend соответствует `tag_id` в БД.

Порядок применения (Supabase Dashboard → SQL Editor):
1. Выполнить целиком `supabase/migrations/202611081815_initial_schema.sql`.
2. Выполнить `supabase/seed.sql` (UPSERT, повторный запуск не создаёт новых id).
3. Table Editor: `tags` — 5 строк, `tasks` — пусто.

Frontend:
- Установлен клиент: `npm install @supabase/supabase-js` (меняет `package.json` и `package-lock.json`)
- `frontend/.env.example` — образец переменных `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`; реальные значения только в `frontend/.env.local` (не в Git)
- `frontend/src/lib/supabase.ts` — единый клиент, при отсутствии переменных выбрасывает ошибку настройки
- `frontend/src/services/tags.ts` — `getTags` читает `tags` (`select('id, name')`, `order('name')`, `abortSignal`), `parseTags` из ЛР 4 сохранён
- В форме добавлена кнопка «Обновить справочник» (`type="button"`, вызывает `retry`, черновик не стирается)
- `frontend/public/demo/tags.json` удалён — больше не источник данных
- Основные задачи по-прежнему локальные (состояние `App`)

Проверки ЛР5:
1. Чтение: открыть форму, в Network найти запрос к `https://<проект>.supabase.co/rest/v1/tags?select=id,name&order=name.asc` — ответ содержит 5 тегов. Создать задачу, открыть редактирование — в `tag` хранится id, в списке показывается name.
2. Ошибка: временно заменить `'tags'` на `'tagz'` в `getTags` — форма показывает ошибку и «Повторить». Вернуть имя.
3. Пустой результат: в SQL Editor `delete from public.tags;` → «Обновить справочник»/«Повторить» — сообщение «Тегов пока нет». Выполнить `seed.sql` снова и нажать «Повторить» без перезагрузки.
4. Изменение имени: `update public.tags set name = 'Учебные задачи' where id = 'study';` → «Обновить справочник» — новое имя при прежнем id, черновик сохранён. Затем вернуть: `update public.tags set name = 'Учёба' where id = 'study';`.
5. Запрет записи: временно выполнить из frontend `supabase.from('tags').insert({ id: 'test', name: 'Тест' })` — ошибка доступа (42501 / permission denied), строка не появляется. `supabase.from('tasks').select('*')` — ошибка доступа, личные строки не читаются. Проверочный код удалить до коммита.
6. Конфигурация: без `.env.local` приложение показывает ошибку «Не настроены переменные Supabase в .env.local»; после возврата файла запускается.
7. `npm run build` проходит с проверкой TypeScript; `npm run preview` — форма читает Supabase.
8. Git видит миграцию, seed, клиент, сервис, `package.json`, lock-файл и `.env.example`, но не видит `.env.local`.
